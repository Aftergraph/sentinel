Review is not verification

Review comments are cheap; merge confidence is not. A comment thread says someone looked. A verdict says this exact commit was checked, names what was found, and cites where.

  • Comments guess. A verdict of SHIP or DO NOT SHIP is issued only against the exact commit it verified.
  • Stale reviews mislead. Reviewing a stale HEAD, re-reporting fixed findings, or approving what was never verified is the failure mode Sentinel refuses: a stale base invalidates the verdict automatically.
  • Evidence, not adjectives. Short verdicts with cited evidence — file and line, for example routes/admin.mjs:41 style references — never praise without a cited check.

Verify

Three properties hold for every verdict. Select each tab:

Each review ends in a merge-ready verdict: SHIP (exit 0) or DO NOT SHIP (exit 1), with findings cited to file and line. Exit 2 means STALE — re-run, never treat it as failure.

Every review appends a content-addressed receipt to the local ledger. Re-running the same HEAD yields the same receipt id — the artifact reads as a certificate, not a chat message.

Rule pack v1.7.0 ships 26 deterministic rules (supported packs: 1.0.0, 1.1.0, 1.2.0, 1.3.0, 1.4.0, 1.5.0, 1.6.0, 1.7.0). Style findings are reported but never block a verdict; which severities block is set by policy file, not by the page.

Exact HEAD

A verdict names the commit it verified. Move the base or the HEAD and the verdict no longer applies — it is invalidated automatically, so nobody merges on yesterday's approval.

  • Verdict is bound to the exact commit reviewed.
  • Stale base invalidates the verdict; exit 2 signals re-run.
  • Same HEAD re-run produces the same receipt id.
